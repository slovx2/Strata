# Song PC 优化筛选与验收 R1

2026-10-03。按照收益、复杂度和风险筛选，最终仅保留同步/布局修正；显存计数和 DeltaNet 候选实测后撤回。没有整体升级 Strata，没有引入新模型、量化或大规模重构。

## 保留的改动

1. **同步及布局修正**：移植 #463 的 adaptive copy 等待、#550 的 residency upload 同步，以及 #546 的全层 fused 缓冲布局条件。分别避免下一轮读取未完成复制的状态、表上传与非阻塞流的竞态、混合量化层误用小缓冲。当前 SC117 的格式全部受 fused 支持，未声称此前已经触发混合格式故障。此组是正确性修正，不将测速差异归因于同步本身。

最终相对进入本轮前的源码净改动为两个运行时文件，38 行新增/12 行删除。引擎仍为 0.1.36 系列。

## 分组测量

固定 RTX 4080 16GB、i5-13600KF、WSL 56GB/16GB swap、SC117 IQ3_S、32K、INT8 KV、MTP spec 4、9 workers、CPU assist 自动、fused、按需视觉。每组独立单轮；先三次预热再三次测量，正式请求输出 128 tokens；全部 cache_n=0。

| 组别 | 891 输入 prefill/decode | 3842 输入 prefill/decode | 4K 首字等待秒 |
| --- | ---: | ---: | ---: |
| 进入本轮前，热服务 | 627.0 / 41.8 | 1447.8 / 42.7 | 2.707 |
| 同步/布局修正，重启后 | 618.5 / 41.4 | 1520.0 / 43.6 | 2.594 |
| 再加 #547，重启后 | 603.5 / 40.1 | 1495.2 / 44.0 | 2.630 |
| 再加 #413，重启后（撤回） | 631.6 / 39.7 | 1482.3 / 44.0 | 2.656 |
| #547 组重启复验（撤回） | 606.7 / 38.2 | 1466.8 / 39.7 | 2.686 |
| #547 组热服务复验（撤回） | 608.5 / 41.8 | 1465.5 / 43.9 | 2.675 |
| 最终保留同步/布局组，重启复验 | 620.4 / 39.8 | 1448.9 / 43.3 | 2.704 |

单位 tokens/s，均为三次中位数。热服务与重启组分开记录；它们的专家缓存热度并不相同。只有每组内提示词和预热流程相同，没有做多轮交替重启 A/B，所以几个百分点不能宣称为稳定因果收益。MTP 接受率会随输出和专家布局变化。

最后复验的 4K prefill 1448.9 与本轮旧版热服务 1447.8 基本持平，decode 43.3 对 42.7 也不能据此宣称稳定提速。1K decode 39.8 低于旧版热服务 41.8；重启后缓存状态、输出与 MTP 接受率并非严格相同。保留正确性修复，不宣称所有输入无退步。

## 为什么撤回或不做

- **#547 显存计数**：单独适配全部五个调用点后，预填借用量从 1585 槽/3.00 GiB 降至 1420 槽/2.69 GiB，锁页内存从 41.74 降至 41.43 GiB。但启动日志明确显示 8192-token 缓冲不适配、降为 6144；15423-token 输入三次 prefill 中位数只有 1801.2 tokens/s，低于此前约 2227。短基准没覆盖这个退步，因此补充长单轮检查有必要。撤回整个补丁，保留旧分配余量；未进一步证明内部失配的具体根因，不把它归为上游所有环境的通用缺陷。
- **#413 DeltaNet**：成功移植、编译，RTX 4080 上 16 种长度（1–4099）新旧输出/状态/FP16 逐位一致，0 failures；但端到端相对 #547 组，约 1K prefill 603.5→631.6、约 4K 1495.2→1482.3，4K decode 同为 44.0。当前快测下没有一致收益，因此撤回 172 行 CUDA 运行时代码及其测试。不能解释为该优化在其他硬件或长输入上无效。
- **#583**：与现有分块、fused ring、#547 的计数逻辑重叠，社区大收益来自多卡长输入和分块档位变化；本机已有 8K chunk，没有充分理由承担重构和交互验证成本。
- **#363 / #415 / #374**：分别涉及验证图/多处专家内核、当前模型仅 1/48 层的 IQ4_XS、多线程 PLE I/O。收益小或与本机瓶颈尚未对应，本轮不扩大改动面。
- **#500 / #443 / #407 tuned**：作者修正后的收益预期很小、平台差异大，或未证明端到端收益；不纳入。
- **CPU 亲和性、profile、MTP 扫描**：保留当前参数，不把多个变量一起改。WSL 暴露的是 10 核/20 线程，不能直接照搬物理 P/E 核绑定；#589 需要代表性路由 trace 才值得应用，不用固定三条快测输入训练 profile。这里未做全面参数搜索，也未宣称当前参数全局最优。
- **#378 / #575 / KV 策略变化**：主要面向大上下文，与当前 32K 快基准不匹配。
- **多卡、DFlash2、BF16 PLE、Responses/增量 tokenizer**：硬件、额外模型/存储、成熟度或目标不符，不作为此次单轮吞吐改造。

## 最终验收

- image-first：图片答案检查通过，TTFT 4.650s，prefill 323.1，decode 29.1 tokens/s。
- image-cached：图片答案检查通过，TTFT 1.229s，prefill 361.3，decode 34.4 tokens/s。
- 在视觉显存已回收状态补充 15423-token 单轮，三次中位数：prefill 2223.9（历史基线 2227.0）、decode 49.5 tokens/s，TTFT 7.014s。
- Anthropic Messages 算术请求通过；Chat Completions 由整套基准覆盖。
- 32K 是容量；没有填满 32K、没有连续对话测试。开放式输出与小型答案检查不能替代全面质量评估。
- 首次图片与同图编码缓存分别记录；未把同图速度解释为 KV 前缀缓存收益。
- **图片紧接长文本的限制**：首次尝试在两条图片后立即发 16K 文本，视觉尚占用借出显存（746 槽/1442 MiB），首个 warmup prefill 达 103.266s（149.4 tokens/s）、decode 21.3 tokens/s，日志有 783 次专家 blob 文件读取及明显 I/O 等待。中止后续客户端测量，让引擎完成在途请求；只有 /status 确认 busy=false、视觉卸载且 vram_lent=false 后才进行本文纯文本 16K 复验。此异常不能隐藏，也不能与纯文本稳定状态混算；尚未对旧二进制做同样图片→长文本 A/B，因此不声称是新回归或已经修复。当前 idle_s=10，但回收只在请求之间执行，连续请求会推迟回收。
