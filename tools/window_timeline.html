如何读图，以及没有测到什么

主图只保留 GPU / CPU 两行；同一行连续且同类的工作合并；GPU 计算为绿色，专家搬运为黄色。GPU 细粒度记录覆盖主模型验证阶段；其他阶段用斜纹表示未细分。主机阶段名称保留在悬浮提示中。

waitA：等待 CPU 路由 / 调度计划；waitB：等待专家就绪标志（已将 GPU 搬运内核与等待拆开；搬运为黄色块）；waitCPU：等待 CPU 专家结果。旧 profile 的 waitB 还包括 GPU 搬运内核，两者之和才可与旧统计比较。GPU 的“PCIe experts compute”是对已搬入专家的计算，不是搬运本身。

GPU 计算和专家搬运使用同一设备时钟。每个采样窗口通过一次同步校准对齐 CPU 时钟，误差范围在图下给出。“trace_clock_setup”属于诊断开销；额外时间戳（包括每层 waitB 拆分点）、同步和 trace 输出也可能改变调度。本报告用来找热点，不能直接替代无插桩性能基准。

所有窗口是真实采样，未把中位耗时拼接成时间线。透明虚线表示已记录等待，斜纹表示未归因区间；不同轨道耗时重叠，不能相加得到总耗时。pcie_frac 是调度比例参数，不是观测等待百分比。

时间线只展示 decode；prefill 不在此细粒度跟踪范围内，仅列请求级概览。上下文 32K 是容量上限，不表示每个请求输入 32K。输入是 4096 token 的网络、数学、中文写作合成用例；先暖机，再独立请求，禁用前缀缓存。
