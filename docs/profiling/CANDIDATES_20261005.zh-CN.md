# Song PC 第二轮优化结果 — 2026-10-05

正式保留弹性 KV 的 256K 容量、RAM 副本保护和图片兼容。其他研究方向保持关闭。按用户要求停止扩展测试；没有运行的对照明确列为暂停。

硬件：RTX 4080 16GB、i5-13600KF、WSL 56GB（未调整）。SC117 IQ3_S、MTP 开启（spec4，verify 最大6）、INT8 KV、CPU workers9、pcie_frac固定0.25。冻结原生基线5bf523a，当前分支4d494f3上的既有功能保留。

## 正式 256K 容量对照

容量262144，实际每条输入4096 token，四类合成内容（网络、Go、中文、数学），每条最多生成192 token，独立请求。每个引擎先预热所有输入，然后各测两遍；顺序为基线/弹性KV/上限32/上限32/弹性KV/基线。每种16次测量，共48次。前缀复用关闭。

|方案|prefill token/s|decode token/s|平均整条耗时|MTP接受率|
|---|---:|---:|---:|---:|
|原基线|1519.98|40.46|7.450s|0.703|
|弹性KV|1623.95|48.44|6.494s|0.704|
|每轮最多换入32专家|1513.77|40.88|7.411s|0.694|

弹性 KV：decode +19.7%，prefill +6.8%，整条耗时 -12.8%。这是256K容量下4K输入的结果，不是满256K输入速度。全部48次测量的引擎专家文件读取和系统swap写出增量均为0。系统磁盘读取仍可能发生，不能说全机完全无I/O。

两次弹性组decode48.03/48.85；两次基线39.12/41.88，仍有漂移。MTP接受率相近。上限32总收益仅约1%，不改变默认96。弹性KV短请求专家缓存4107槽，原基线2471槽；专家更常驻GPU是主要设计目的。

## 容量与图片验证

修复此前原型的两个限制：图片尾部借还与KV洞独立管理；可能被KV驱逐的专家保留RAM副本，不依赖GGUF回读。

同一进程完成32K→图片→128K（图片仍占显存）→图片→归还→240K→短请求缩容。另一次实际262080-token输入，在图片编码器借用1408MiB时，KV实际增长至262144 cells / 3.35GiB，生成32 token，随后再识图、归还、缩容通过。满输入prefill257.78s、decode886.3ms；这是一条功能验收，不是长输入性能对照。最低系统可用RAM约4.7GiB，未观察到该请求swap写出。所有请求专家文件读取0。

最终二进制已完成：图片→262080输入（实际满KV）→KV仍满时归还图片显存→缩容→再次识图，识图正确且同PID。脚本最后因重复图片命中图片嵌入缓存、没有重新借显存而触发过严断言，整份测试记录仍标为未完成，不能称整项通过。使用不同图片的补测已按用户要求取消；未再运行生产API或启停脚本冒烟测试。
